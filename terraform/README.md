# AWS infrastructure (dev)

Region `ap-southeast-2`. Local Terraform state (single developer).

| Piece | Service |
|---|---|
| Backend | Lightsail container service, image in private ECR |
| Web | S3 (private) + CloudFront (OAC, SPA fallback to `index.html`) |
| Database | RDS Postgres 18 (`db.t4g.micro`), **public in dev** (TLS forced) |
| Secrets | Secrets Manager: the RDS-managed DB secret (`rds!db-...`, native rotation) and one app secret `<name>/backend` (Clerk keys) |
| IAM | `*-deployer` (push/deploy only), `*-backend-runtime` (read those 2 secrets only; its key is handed to Lightsail) |

```
terraform/
  modules/{network,database,secrets,backend,ecr,deployer,web}
  environments/dev      # wires the modules together
deploy/                 # scripts used by the root Makefile
```

## First-time setup

1. **Provision** (with an admin AWS profile): `make tf-init && make tf-apply`.
2. **Clerk secret** (one JSON secret; the value never goes in Terraform state):
   ```sh
   T="terraform -chdir=terraform/environments/dev"
   aws secretsmanager put-secret-value --secret-id "$($T output -raw backend_secret_arn)" \
     --secret-string '{"CLERK_SECRET_KEY":"sk_...","CLERK_WEBHOOK_SIGNING_SECRET":"whsec_..."}'
   ```
3. **Deployer profile**: create the CLI profile the scripts use (`AWS_PROFILE`, default `sumni-deployer`):
   ```sh
   aws configure --profile sumni-deployer set region ap-southeast-2
   aws configure --profile sumni-deployer set aws_access_key_id "$($T output -raw deployer_access_key_id)"
   aws configure --profile sumni-deployer set aws_secret_access_key "$($T output -raw deployer_secret_access_key)"
   ```
4. **Backend**: `make ecr-push` then `make lightsail-deploy` (optional `TAG=...`; default is the short git SHA, and ECR tags are immutable). Needs `docker buildx`, `jq`, `terraform`. The container runs migrations on startup.
5. **Web**: `VITE_CLERK_PUBLISHABLE_KEY=pk_... make web-deploy`. `VITE_API_BASE_URL` defaults to the Lightsail URL.
6. Add the CloudFront URL (`web_url` output) to Clerk's allowed origins. The deploy script already sets it as `CORS_ALLOWED_ORIGINS` and `CLERK_AUTHORIZED_PARTIES` on the backend.

Order matters: deploy the backend *after* the Clerk secrets are set (the app fails to start on an empty secret), and the web *after* the backend so the API URL exists. The CloudFront URL is only known after step 1, so the backend deploy in step 4 picks it up automatically.

## CI/CD (GitHub Actions, backend)

Terraform runs **locally only** (it creates the AWS resources). CI never runs terraform: it gets every value from the `dev` GitHub environment below.

Two manually triggered workflows, both using the `dev` GitHub environment:

1. **Backend Commit Stage**: lint, test, build, scan and push the image to ECR. The tag is the **commit SHA** (generated by Actions; the job summary shows it). Re-running on a published SHA skips the push.
2. **Deploy Backend**: takes the image `tag` (a published SHA) as input and creates the Lightsail deployment through `deploy/lightsail-deploy.sh`. Rollback = deploy an older SHA. It does not rebuild.

Configure the `dev` environment (values from `terraform output`):

| Kind | Name | Source |
|---|---|---|
| secret | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | `deployer_access_key_id`, `deployer_secret_access_key` |
| secret | `RUNTIME_ACCESS_KEY_ID`, `RUNTIME_SECRET_ACCESS_KEY` | `runtime_access_key_id`, `runtime_secret_access_key` (handed to Lightsail so the app can read its 2 secrets) |
| var | `AWS_REGION` | `region` |
| var | `ECR_REPOSITORY_URL` | `ecr_repository_url` |
| var | `LIGHTSAIL_SERVICE` | `lightsail_service` |
| var | `DB_HOST`, `DB_NAME` | `db_host`, `db_name` |
| var | `WEB_URL` | `web_url` |
| var | `DB_SECRET_ARN`, `APP_SECRET_ARN` | `db_secret_arn`, `backend_secret_arn` |

Sensitive outputs: `terraform -chdir=terraform/environments/dev output -raw runtime_secret_access_key`.

### Web workflow (`deploy-web`)

Builds in `web-commit-stage`, then syncs `web/dist` to S3 and invalidates CloudFront. It uses the same `dev` environment and deployer credentials as the backend, plus:

| Kind | Name | From terraform output |
|---|---|---|
| var | `WEB_BUCKET` | `web_bucket` |
| var | `WEB_DISTRIBUTION_ID` | `web_distribution_id` |
| var | `VITE_API_BASE_URL` | `api_url` |
| var | `VITE_CLERK_PUBLISHABLE_KEY` | (Clerk publishable key) |

`AWS_REGION` and `WEB_URL` are shared with the backend workflow.

## Connecting to the dev DB

Public endpoint, TLS required. User and password live in the RDS-managed secret (read it with your admin profile; the deployer cannot):
```sh
aws secretsmanager get-secret-value --secret-id "$($T output -raw db_secret_arn)" --query SecretString --output text
psql "host=$($T output -raw db_host) dbname=sumni_finance user=<username> sslmode=require"
```
`db_allowed_cidrs` defaults to `0.0.0.0/0` because Lightsail has no static egress IP. Restrict it to your IP in `terraform.tfvars` if you don't need Lightsail to reach the DB.

## Secret rotation

The backend reads the DB secret (RDS-managed) and the app secret (`<name>/backend`) from Secrets Manager **at startup** (`configs.LoadSecrets`, env `AWS_SECRET_DB_ARN` / `AWS_SECRET_APP_ARN`) with the runtime IAM user's key. After a rotation, or after changing the Clerk values with `put-secret-value`, redeploy or restart the container to pick up the new values (re-run Deploy Backend with the same tag, or `make lightsail-deploy TAG=<sha>` locally).
The DB secret is RDS-managed, so you can turn on automatic rotation for it in the RDS console or with `aws rds modify-db-instance --manage-master-user-password --rotate-master-user-password`.

## Going to prod later

- `db_public = false` in `network` and `database`: DB subnets become private (no internet gateway).
- `db_allowed_cidrs` = the Lightsail VPC CIDR (`172.26.0.0/16`) only.
- `enable_vpc_peering = true` in `backend`. Lightsail only peers with the region's **default VPC**, so the prod DB has to live there (or be reached another way). A route to `172.26.0.0/16` through the peering connection must also be added to the DB route table (`db_route_table_id` output). This is **not automated yet**.
- `deletion_protection = true`, `skip_final_snapshot = false`, longer `backup_retention_days`, `recovery_window_in_days = 7` or more.

### Querying a private DB
The RDS console Query Editor supports Aurora only, not plain RDS Postgres. Options: an EC2 bastion with SSM port forwarding (no open ports), or temporarily setting `db_public = true`. No bastion module exists yet; add one when prod is created.

## Cost notes
RDS `db.t4g.micro` with 20 GB and S3/CloudFront fit the 12-month free tier. The Lightsail container service (`nano`) is billed monthly (about $7), apart from any new-account trial. Secrets Manager charges per secret (2 secrets) and is not in the free tier.
